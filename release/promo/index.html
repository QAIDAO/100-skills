Problem anatomy

一道题长什么样

  1. 01研究体系算的是什么
  2. 02可观测量用什么数回答
  3. 03经典基线经典能做到哪
  4. 04量子方法的角色量子放在哪一步
  5. 05研发决策支撑什么判断

每道题还给出五条「什么算解」：模型对应、可观测量与不确定度、同模型经典对照、可复现性与成本、对研发决策的支撑。负结果同样接受。

    Reference runs

    你不是从零开始

    100 道题中有 80 道附有我们已完成的计算与模拟记录，成功和失败都摆出来。参照不代表最优解，它告诉你从哪里接着做、哪条路已经试过。

    C08 · RNA 二级结构与假结

    能量最低的解，不一定是对的解

    在一个真实的 33 核苷酸适配体上，最低目标分的解确实能找到，但它比真实结构多出两对不存在的配对；真实结构也在可行空间里，得分却低得多。

    问题出在能量模型本身，换更强的求解器也解决不了。这样的负结果同样写进参照，能帮后来者少走弯路。

    • 所有参照都在经典计算机上执行，不包含真机结果。
    • 按项目当前记录，原应用目标完成数为 0，这些题目都还开放着；我们不声称量子优势。
    • 原始数据与第三方数据集不随题库发布，每题的 evidence.json 记录来源文件的 SHA-256。

    Contribute

    你的解法会去哪里

    想先聊思路，或觉得某道题的标准需要细化，直接开 issue。负结果和部分结果同样欢迎。

    1. 01

      挑一道题

      读它的 PROBLEM.md：五段题面、五条验收标准和现有参照都在里面。

    2. 02

      按模板提交

      把解法放进 solutions/<题号>/<名字>-<短名>/，包括 SOLUTION.md 与 solution.json。

    3. 03

      校验后开 PR

      本地跑一遍校验器，用 git commit -s 签名提交，CI 会再检查一次。

    python3 -I release/tools/check_submissions.py --root .
    1. 提交按模板提交，CI 校验格式
    2. 审核五条验收标准都有回应
    3. 复现他人按记录独立重跑
    4. 采纳记入这道题的现有参照
    5. skill同类方法积累后提炼，署名全部来源作者
    • 记入参照。被采纳的解法记入这道题的现有参照，后来的人从你停下的地方接着做。
    • 署名进 skill。同一类方法积累到足够多的采纳解法后提炼为 skill，署名全部来源解法的作者。
    • 负结果同样算数。一条在给定预算下走不通的路线，写清楚了，就是别人不必再走的弯路。
    • 公开可复用。题面与文档 CC BY 4.0，代码 Apache-2.0，任何人都能在你的工作上继续。
